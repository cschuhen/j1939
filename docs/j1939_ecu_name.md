# J1939 ECU NAME Specification

Every Electronic Control Unit (ECU) on a J1939 network must possess a unique **64-bit NAME**. This identifier is critical for address claiming, network administration, and node identification.

---

## 64-bit NAME Field Breakdown

The 64-bit integer is structured into 10 distinct fields. The fields represent either fixed (enumerated) configurations or numerical counters/instances.

### Field Layout Table

| Bit Range | Size (Bits) | Field Name | Type | Description |
| :--- | :---: | :--- | :---: | :--- |
| **63** (MSB) | 1 | **Arbitrary Address Capable** | **Fixed** | `1` = Dynamic address resolution allowed.<br>`0` = Fixed address mandatory. |
| **62 - 60** | 3 | **Industry Group** | **Fixed** | Sector class (e.g., Agricultural, Marine, On-Highway). |
| **59 - 56** | 4 | **Vehicle System Instance** | **Number** | Identifies which instance of a Vehicle System this is (`0` to `15`). |
| **55 - 49** | 7 | **Vehicle System** | **Fixed** | Vehicle type within the Industry Group. |
| **48** | 1 | **Reserved** | **Fixed** | Reserved by SAE. Must always be `0`. |
| **47 - 40** | 8 | **Function** | **Fixed** | Specific operational function (e.g., Engine, Transmission). |
| **39 - 35** | 5 | **Function Instance** | **Number** | Identifies which instance of a Function this is (`0` to `31`). |
| **34 - 32** | 3 | **ECU Instance** | **Number** | Identifies which physical ECU performs the Function (`0` to `7`). |
| **31 - 21** | 11 | **Manufacturer Code** | **Fixed** | Unique ID assigned by SAE/ISOBUS to manufacturers. |
| **20 - 0** (LSB) | 21 | **Identity Number** | **Number** | Unique manufacturer-specific number (e.g. Serial Number). |

---

## Field Types & Registration

### 1. Fixed (Enumerated) Fields
These fields use standardized values defined by SAE and the ISOBUS committee. A complete registry of these assignments can be retrieved from:
* **Official ISOBUS Registry**: [isobus.net/isobus](https://www.isobus.net/isobus/)

Key fixed fields:
* **Industry Group**: Standard groups include:
  * `0`: Global
  * `1`: On-Highway Equipment
  * `2`: Agricultural and Forestry Equipment
  * `3`: Construction Equipment
  * `4`: Marine Equipment
  * `5`: Industrial/Process Control
* **Vehicle System**: Dependent on the Industry Group. For example, in Agricultural (`2`), systems include Tractor, Harvester, etc.
* **Function**: Defines the type of device. Standard codes:
  * `0`: Engine
  * `3`: Transmission
  * `116`: Virtual Terminal (ISOBUS VT)
  * `130`: Task Controller (ISOBUS TC)
* **Manufacturer Code**: Standardized vendor identifiers (e.g., John Deere, Bosch, Cummins).

### 2. Number Fields
These fields are configured by the integrator or generated by the hardware:
* **Vehicle System Instance**, **Function Instance**, and **ECU Instance**: Used to distinguish duplicate systems on the same network (e.g. dual engine systems). They must start at `0`.
* **Identity Number**: Must be uniquely assigned by the manufacturer to ensure no two physical devices ever share the exact same 64-bit NAME, even if they share the same manufacturer, function, and instances.

## Bit Extraction & Packing (Reference Guide)

### Parse 64-bit NAME
To parse a 64-bit integer (`u64`) into its constituent fields:

* **Arbitrary Address Capable**: `(name >> 63) & 0x01`
* **Industry Group**: `(name >> 60) & 0x07`
* **Vehicle System Instance**: `(name >> 56) & 0x0F`
* **Vehicle System**: `(name >> 49) & 0x7F`
* **Reserved**: `(name >> 48) & 0x01`
* **Function**: `(name >> 40) & 0xFF`
* **Function Instance**: `(name >> 35) & 0x1F`
* **ECU Instance**: `(name >> 32) & 0x07`
* **Manufacturer Code**: `(name >> 21) & 0x7FF`
* **Identity Number**: `name & 0x1FFFFF`

### Packing Fields into a 64-bit NAME (Rust Example)

```rust
pub struct EcuName {
    pub arbitrary_address_capable: bool,
    pub industry_group: u8,
    pub vehicle_system_instance: u8,
    pub vehicle_system: u8,
    pub function: u8,
    pub function_instance: u8,
    pub ecu_instance: u8,
    pub manufacturer_code: u16,
    pub identity_number: u32,
}

impl EcuName {
    pub fn to_u64(&self) -> u64 {
        ((self.arbitrary_address_capable as u64) << 63) |
        (((self.industry_group & 0x07) as u64) << 60) |
        (((self.vehicle_system_instance & 0x0F) as u64) << 56) |
        (((self.vehicle_system & 0x7F) as u64) << 49) |
        // Bit 48 is reserved (0)
        (((self.function & 0xFF) as u64) << 40) |
        (((self.function_instance & 0x1F) as u64) << 35) |
        (((self.ecu_instance & 0x07) as u64) << 32) |
        (((self.manufacturer_code & 0x7FF) as u64) << 21) |
        ((self.identity_number & 0x1FFFFF) as u64)
    }

    pub fn from_u64(name: u64) -> Self {
        Self {
            arbitrary_address_capable: ((name >> 63) & 0x01) == 1,
            industry_group: ((name >> 60) & 0x07) as u8,
            vehicle_system_instance: ((name >> 56) & 0x0F) as u8,
            vehicle_system: ((name >> 49) & 0x7F) as u8,
            function: ((name >> 40) & 0xFF) as u8,
            function_instance: ((name >> 35) & 0x1F) as u8,
            ecu_instance: ((name >> 32) & 0x07) as u8,
            manufacturer_code: ((name >> 21) & 0x7FF) as u16,
            identity_number: (name & 0x1FFFFF) as u32,
        }
    }
}
```
